# AccuStandard Writing Style Guide

This guide sets the writing standard for the AccuStandard Medical ERP & Supply
Chain Dashboard. Apply it to current UI copy, help text, documentation, guides,
release notes, and user-facing error messages.

## Voice and tone

- Write in English (US).
- Sound professional, conversational, and engaged. Be calm, specific, and helpful.
- Put the most important information first. Tell the reader what happened and what
  to do next.
- Use active voice and concrete verbs. Address the reader directly when that makes
  the instruction clearer.
- Keep one idea per sentence when practical. Prefer short paragraphs and useful
  headings over long blocks of text.

## Plain language and consistency

- Use familiar words and explain an acronym on first use unless it is already a
  standard label in the product (for example, PO, RR, SOA, QBO, WMA, and COSO).
- Use sentence case for new UI labels, buttons, headings, and helper text. Keep
  formal print templates and controlled status values unchanged when they are part
  of an approved document or workflow.
- Use the same term for the same concept throughout the app. Preserve API routes,
  storage keys, status enums, role names, and audit-event text when they are part
  of an integration or control.
- Prefer specific behavior over promises. State what the current demo does, what
  it does not do, and what evidence is required.

## Proofreading checklist

Before committing copy, check spelling, punctuation, capitalization, agreement,
pronoun references, dates, units, and acronym definitions. Read the text in its
actual UI context. Confirm that labels describe the action the button performs and
that error messages explain the problem and the next step.

## Avoid AI-sounding copy

Remove filler, hype, and vague claims. Avoid phrases such as “seamless,” “robust,”
“comprehensive,” “leveraging,” “in today's fast-paced world,” “best-in-class,”
“unlock” (unless it names a literal workflow action), and “revolutionary.” Do not
repeat the same benefit in several forms, stack adjectives, or claim certainty the
system cannot verify. Prefer a plain description of the control, result, or limit.

Historical prompts, transcripts, and superseded drafts in
`to-review-and-delete/` are retained as an archive. Do not rewrite them as if they
were current product guidance.
